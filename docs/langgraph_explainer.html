LangGraph for the ETL pipeline

LangGraph is a small library for building a workflow as an explicit graph — named steps (nodes) connected by edges, passing a shared state along. We used it to re-express the DR ETL's per-combination agent flow. Same agents, same Snowflake in/out, same result — only the orchestration in the middle changed.

The shift, in one picture

Before — one long imperative loop (logic buried in nesting)

for combination in combinations: payload = build() if not healthy: continue correlation = call_correlation() pattern = retry(call_pattern) if 0 patterns: defaults; skip reimbursement + recommendation else: for p in patterns: reimbursement(); recommendation() policy = call_policy() # always, but easy to miss result = {...} # ~1,100 lines, hard to test a branch

After — the compiled graph (generated from the real StateGraph)

Traditional ETL vs LangGraph

AspectTraditional ETLLangGraph
Flow visibilityBuried in nested loopsExplicit, renderable graph
Branching / routingHidden if / else indentationDeclarative conditional edges
Test one branchMust run the whole thingNode in isolation (stub agents)
State between stepsAd-hoc local variablesTyped shared state
Checkpoint / resumeHand-rolledBuilt in
Live progressScrape the logsNative streaming (▶ node ✓)
Add / reorder a stepEdit a ~1,100-line functionAdd a node + an edge
DependenciesNone extraNeeds langgraph
Learning curveFamiliarNodes / edges / state concepts
PerformanceBaselineSame — no speed gain
Best forShort, linear transformsBranching, retrying, inspectable flows

Not a replacement for ETL — a replacement for the control flow. Data loading and storage stay the same proven helpers; only the decision logic between them becomes a graph.

Benefits — what we actually got

See the logic

The "skip when 0 patterns, but always run policy" rule is now explicit edges, not buried nesting.

Watch it live

--stream prints ▶ node ✓ per stage; a notebook view animates the active node.

Test each piece

All branches verified in seconds with stubbed agents — no Snowflake, no live API.

Resumable

Built-in checkpointing fits the pipeline's existing "resume a failed run".

Easy to evolve

Add a node + an edge to change the flow — no rewriting a 1,100-line loop.

Consistent

Matches the idiom already used in the main app's orchestrator.py.

When to reach for it

Use LangGraph when the flow branches, retries, fans out, or needs to be inspected, resumed, or explained. Keep it plain when the job is a short, linear, one-shot transform. The DR ETL — agents, retries, a 0-vs-many-patterns branch, a step that must always run — sits squarely in the first camp.

Same agents · same Snowflake in/out · same result_record — the orchestration became a graph.
